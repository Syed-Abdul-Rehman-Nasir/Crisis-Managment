# CIRO: Crisis Intelligence & Response Orchestrator - App Development Blueprint

## 1. Project Context and Vision
CIRO is an advanced multi-agent system designed to detect, classify, and respond to crises in real-time. Originally built as a proof-of-concept web dashboard for a hackathon, CIRO utilizes an orchestration of smaller agentic components alongside a centralized LLM (Google Gemini) to synthesize diverse signals (social media, weather, traffic, emergency calls) into actionable resource allocation and public broadcast plans.

**Goal for App Development**: Transition this intelligent backend from a web-only demo to a robust backend capable of serving a cross-platform mobile application (React Native / Flutter) used by on-ground responders and citizens.

## 2. Architecture & Tech Stack

### Current Stack
- **Backend**: FastAPI (Python), Uvicorn, Pydantic, WebSockets.
- **Frontend**: React (Vite), Tailwind CSS, Leaflet Maps, Lucide Icons.
- **Intelligence**: Google Gemini API for natural language reasoning, signal fusion, explanation generation, and stakeholder message synthesis.
- **Deployment**: Configured for Render (Backend) and Vercel (Frontend).

### Proposed Mobile App Architecture
- **Mobile Client**: React Native or Flutter.
- **API Communication**: REST for CRUD operations and crisis fetching; WebSockets for real-time live signal streaming and instant alerts.
- **Push Notifications**: Firebase Cloud Messaging (FCM) to deliver instant stakeholder messages to users based on location.
- **Offline Mode**: Local SQLite database to cache active crises and standard operating procedures (SOPs).

## 3. Core Workflows & Logic

### 3.1. The Agentic Pipeline
The core logic resides in `backend/agents/agent_configs.py` and `backend/main.py`. The `OrchestrationPipeline` runs sequentially:
1. **SignalFusionAgent**: Aggregates raw signals (social, weather, traffic) into a cohesive payload. Gemini assigns credibility scores.
2. **ClassificationAgent**: Analyzes the fused payload to categorize the crisis (e.g., Flood, Earthquake, Fire), assess severity, and calculate confidence.
3. **ResourceAllocationAgent**: Evaluates available resources (ambulances, rescue teams, fire trucks) and allocates them based on crisis severity and location. Gemini explains the reasoning and trade-offs.
4. **ResponsePlanningAgent**: Generates actionable, step-by-step tasks to mitigate the crisis (e.g., "Reroute traffic", "Evacuate Zone B").
5. **StakeholderCommunicationAgent**: Drafts multilingual (English/Urdu) alerts for public advisories, hospital trauma units, and utility companies.
6. **VerificationAgent**: Continuously monitors incoming signals to detect contradictions and retract false positives (e.g., mistaking a water main burst for a natural flood).

### 3.2. Data Flow
1. **Ingestion**: Raw signals generated by `backend/data/generators.py` are pushed into a `collections.deque` buffer.
2. **Streaming**: `GET /ws/signals` (WebSocket) streams these signals to the client in real-time.
3. **Trigger**: `POST /api/trigger` simulates an event (e.g., `g10_flood`, `karachi_industrial_fire`). This endpoint triggers the entire `OrchestrationPipeline` synchronously and caches the result in `app.state`.
4. **Retrieval**: The frontend uses `GET /api/alerts/comparison`, `GET /health`, and WebSocket streams to display the Tactical Operations Center dashboard.

## 4. Migration to Mobile App Development

### Phase 1: API Hardening
- **Authentication**: Implement JWT-based auth (e.g., FastAPI Users or Firebase Auth) to secure endpoints. Differentiate between "Responder", "Admin", and "Citizen" roles.
- **Database Integration**: Replace `app.state` in-memory storage with PostgreSQL (via SQLAlchemy or SQLModel) to persist crisis events, trace logs, and resources.
- **Pagination & Filtering**: Add query parameters to `/api/crisis` and `/api/signals` to allow the mobile app to fetch data efficiently.

### Phase 2: Mobile UI/UX Design
- **Citizen View**: Focus on push notifications, localized maps showing danger zones, and simple reporting interfaces for users to submit raw signals.
- **Responder View (Tactical Ops)**: A mobile-adapted version of the web dashboard. Needs an "Active Threats" list, resource deployment status, and the ability to acknowledge or update action statuses.
- **Map Integration**: Use `react-native-maps` to render crisis radii, responder locations, and safe routing paths.

### Phase 3: Real-Time Communication
- Replace the polling mechanism in the demo with robust WebSocket reconnection logic in the app.
- Integrate APNs (Apple) and FCM (Firebase) to push StakeholderCommunicationAgent messages directly to lock screens.

## 5. Directory Structure Overview
- `backend/models/`: Pydantic schemas defining the data contracts (Crisis, Signal, Allocation).
- `backend/api/`: FastAPI route handlers exposing the core logic.
- `backend/agents/`: Definitions for each step of the pipeline.
- `backend/intelligence/`: Interfaces to the Gemini API (`gemini_fusion.py`), baseline algorithms, and verification logic.
- `backend/data/`: Mock signal generators (Weather, Social, Traffic).
- `backend/reasoning/`: AI explainer modules (`allocation_explainer.py`).
- `frontend/src/App.jsx`: The React-based Tactical Operations Center UI.

## 6. How to Run Locally
1. Navigate to `backend/`.
2. Activate virtual environment: `.\venv\Scripts\activate`.
3. Install dependencies: `pip install -r requirements.txt`.
4. Run server: `uvicorn main:app --reload`.
5. Navigate to `frontend/`.
6. Run client: `npm run dev`.

By understanding this document, a mobile development team can seamlessly replace the `frontend/` React codebase with a React Native or Flutter application while leveraging the intelligent, multi-agent FastAPI backend as the central source of truth.
